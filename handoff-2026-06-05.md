## 1. VISIÓN GENERAL

**NGT (Numa Golf Tour XIV 2026)** es una web app de Google Apps Script para gestionar un torneo de golf con:
- Armar automáticamente líneas de juego (3-4 jugadores) con inteligencia de horarios y restricciones
- Calcular handicap de juego dinámicamente (WHS Index × Slope / 113)
- Cargar tarjetas de scores hoyo por hoyo
- Visualizar resultados (Stableford + Match)
- Leaderboard, perfiles de jugadores, y gestión administrativa

**Paso 2: Armar Líneas**

- Backend arma líneas automáticamente con algoritmo backtracking
- Preview de líneas + matches propuestos
- Admin puede agregar/editar matches manualmente antes de confirmar
- Botón "✓ Crear Fecha" guarda todo

### B. Algoritmo de Armar Líneas (`armarLineas_`)

**Entrada:**
```json
{
  "fecha": 4,
  "jugadores": [{"matricula": "123", "hcp": 18}, "..."],
  "prioridades": [{"matricula": "123", "posicion": "primera"}, "..."]
}
```

**Lógica:**

1. **Cálculo de división de líneas** — maximiza líneas de 4, minimiza de 3:
   - N % 4 = 0 → todas de 4
   - N % 4 = 1 → 3 líneas de 3, resto de 4 (ej: 17 jugadores → 2×4 + 3×3)
   - N % 4 = 2 → 2 líneas de 3, resto de 4 (ej: 18 jugadores → 3×4 + 2×3)
   - N % 4 = 3 → 1 línea de 3, resto de 4 (ej: 15 jugadores → 3×4 + 1×3)
   - **No puede haber líneas de 2 jugadores**

2. **Lectura de restricciones:**
   - `MATCH!CA1:CS19` (matriz 18×18) → qué matches ya se jugaron
   - `MATCH!BZ:CB` (flat list: fecha, lineNum, apodo) → quién compartió línea en las últimas 2 fechas

3. **Backtracking recursivo (`buildLines`):**
   - Prueba todas las combinaciones de k jugadores
   - Calcula score por combinación:
     - **Match repetido:** +10.000 (muy penalizado, pero nunca bloquea)
     - **Línea repetida últimas 2 fechas:** +1.000 por pareja
     - **HCP spread:** +1 por punto de diferencia
   - Elige la combinación con menor score

4. **Para líneas de 4: `bestFourDiv`**
   - Prueba 3 divisiones posibles: {A,D}vs{B,C}, {A,B}vs{C,D}, {A,C}vs{B,D}
   - Genera 4 matches por división: A-C, A-D, B-C, B-D
   - Penaliza matches repetidos, siempre devuelve la mejor opción

5. **Post-proceso: Reordenar por prioridades (garantizado)**
   - Líneas con jugadores "primera" → al inicio
   - Líneas con jugadores "ultima" → al final
   - Este paso es post-proceso (no heurística): garantiza el resultado independientemente del backtracking

**Salida:**
```json
{
  "ok": true,
  "lines": [
    {
      "lineNum": 1,
      "players": [{"matricula": "123", "apodo": "TRIMBA", "hcp": 18}],
      "matches": [{"j1": "123", "j2": "456"}]
    }
  ]
}
```

### C. Cálculo Dinámico de HCP de Juego

**Fórmula WHS:** `HCP_Juego = round(HCP_Index × Slope / 113)`

**Flujo:**
1. **Cada jueves a las 8am (trigger automático):**
   - `actualizarHcpIndices_()` → UrlFetch paralelo a `vistagolf.com.ar`
   - Regex: `/HCP\s+Index\s*:?\s*([0-9]+[.,][0-9]+|[0-9]+)/i`
   - Guarda en JUGADORES col E (HCP_INDEX), col F (HCP_UPDATED)
   - Maneja separadores decimales coma y punto (ej: "17,5" → 17.5)

2. **Al crear fecha:**
   - `buildHcpJuegoMap_(canchaId, canchaName, teeColor)` calcula HCP para cada jugador
   - Lee: JUGADORES (HCP_INDEX) + NGT DB Rating sheet (Slope del tee)
   - Auto-rellena col E de TARJETAS al crear la fecha

3. **En la tarjeta:**
   - Banner muestra: WHS Index + array de tees con HCP, slope, rating, % 85

### D. Gestión de Fechas (Panel Admin)

**Datos:**
- Jugadores seleccionados + invitados
- Cancha + Color de salida
- Matches (auto-generados o manuales)

**Dobles (Stableford × 2):**
- Card separada con checkboxes por jugador
- Botón "💾 Guardar Dobles" → `setDoblesFecha_` actualiza SCORE sheet
- **Se configura desde Gestionar Fecha** (no en el wizard — el admin no sabe quién juega doble hasta minutos antes)

**Armar Líneas (desde gestionar):**
- Click en "⚡ Armar líneas" abre modal de prioridad (mismo que wizard)
- Backend aplica mismo algoritmo

**Tarjetas:**
- Editor por jugador: 18 inputs para hoyos + botón "Cargar"
- Lock optimizado: lee antes del lock, escribe dentro, flush después
- Soporta 18 jugadores cargando simultáneamente

### E. Botón "FECHA X" en Home + Modal de Líneas

**Lógica de visibilidad:**
1. `getFechaActiva_()` busca en FECHA_META la fecha más reciente con líneas confirmadas
2. **Condición activa:** tiene lineas en FECHA_META AND no todos los jugadores tienen hoyo 1 cargado (col H de TARJETAS)
   - ⚠️ El HCP (col E) NO sirve como indicador: se auto-rellena al crear la fecha
   - La fecha desaparece cuando TODOS los jugadores cargan su primera tarjeta
3. Independiente del calendario (CALCULOS) → funciona con cualquier fecha, incluso pruebas

**Flujo:**
```
Home carga → ngtInitData() → GET initData API
  → recibe fechaActiva {fechaNum, cancha, horario, hasLineas}
  → applyFechaActiva() muestra botón "FECHA X"
  → Click → openVerLineas(num) → GET fechaLineas API
  → renderFechaCard_() → modal con líneas, jugadores, HCPs, matches
```

**Invalidación de cache:**
- Al crear fecha: `finalizarWizard()` limpia `sessionStorage.ngt_fechaActiva` y llama `ngtInitData()`
- Al borrar fecha: `_doEliminarFecha()` limpia sessionStorage y oculta botón inmediatamente
- Backend `crearFecha_()` invalida caches de CacheService

### F. fecha-4.html — Página Dinámica de Líneas

Archivo estático en el repositorio que al abrirse llama al API y renderiza los datos reales:
- Misma estética que el card modal del home
- HCPs reales por tee (Blancas y Azules)
- Matches reales de la fecha
- Horarios calculados (+10 min por línea desde el horario de salida)
- Se actualiza automáticamente si el admin edita la fecha (no requiere re-deploy)
- URL compartible para que jugadores vean sus líneas


### C. Estructura MATCH Sheet — Matches (2 filas por match)

```
Fila N:   [fecha] [matricula_J1] [nombre_J1]
Fila N+1: [fecha] [matricula_J2] [nombre_J2]
```

⚠️ **Importante:** cada match ocupa 2 filas consecutivas, NO una fila con j1 y j2 en columnas distintas.

### D. Estructura MATCH!BZ:CB — Historial de Líneas

```
BZ(fecha) | CA(lineNum) | CB(apodo)
4         | 1           | TRIMBA
4         | 1           | FRANCO
4         | 2           | CARLOS
...
```

Permite saber quién compartió línea en cada fecha específica → regla "no repetir línea en últimas 2 fechas".

## 6. CONSIDERACIONES TÉCNICAS CLAVE

### A. Matches en MATCH Sheet: 2 filas por match ⚠️ CRÍTICO

**Crítico para `getFechaLineas_` y cualquier lectura de matches:**

```javascript
// CORRECTO: leer de a pares
for (var ri = 0; ri + 1 < mData.length; ri += 2) {
  const f1 = String(mData[ri][0]).trim();
  const f2 = String(mData[ri + 1][0]).trim();
  if (f1 !== String(fecha) || f2 !== String(fecha)) continue;
  const j1 = String(mData[ri][1]).trim();
  const j2 = String(mData[ri + 1][1]).trim();
  // ...
}

// INCORRECTO (bug previo): asumir j1 y j2 en misma fila
mData.forEach(row => {
  const j1 = row[1];  // mat del jugador 1
  const j2 = row[2];  // ← esto es el NOMBRE de j1, no la mat de j2
});
```

### B. HCP: No usar col E como indicador de "tarjeta cargada" ⚠️ CRÍTICO

Col E (HCP de juego) se **auto-rellena al crear la fecha**, no cuando el jugador carga scores.  
Usar HCP como indicador produce falsos positivos en tres lugares — todos ya corregidos:

| Lugar | Síntoma del bug | Campo correcto |
|-------|----------------|----------------|
| `getFechaActiva_()` | Botón FECHA no aparecía en home | Col H (Hoyo 1) en TARJETAS |
| `getMisFechas_` + `showMitFechas` | Tarjeta aparecía como "ya cargada" | `hasScores` (col H) |
| `getFechasConEstado_` | Fecha marcada "completa" antes de jugar | (pendiente revisar si aplica) |

**Regla universal:**
```javascript
// CORRECTO — indica si el jugador cargó scores
const hoyo1 = row[6]; // col H, en rango getRange(2, 2, n, 7) → B=0,...,H=6
const cargado = hoyo1 !== '' && hoyo1 !== null && hoyo1 !== undefined;

// INCORRECTO — el HCP siempre tiene valor desde la creación de la fecha
const cargado = row[3] !== ''; // col E = HCP → siempre true, no sirve
```

**`getMisFechas_`** devuelve el campo `hasScores: bool` para que el frontend sepa  
si el jugador realmente cargó scores (no solo si tiene HCP asignado).

### C. Prioridades de Líneas: Post-Proceso, No Heurística

El backtracking ignora prioridades (optimiza score). Las prioridades se aplican **después**:
```javascript
var firstLines  = lines.filter(l => l.players.some(p => primerSet[p.matricula]));
var lastLines   = lines.filter(l => l.players.some(p => ultimaSet[p.matricula]));
var middleLines = lines.filter(l => !hasFirst(l) && !hasLast(l));
lines = firstLines.concat(middleLines).concat(lastLines);
```
Esto garantiza el orden independientemente del backtracking.

### D. Algoritmo: Soft Constraints (No Hard)

Matches y líneas repetidas son **penalizaciones**, nunca bloqueos:
- Match ya jugado: +10.000 puntos
- Línea compartida últimas 2 fechas: +1.000 puntos
- HCP spread: +1 punto por diferencia

El algoritmo siempre produce una solución. En torneos avanzados donde inevitablemente hay repeticiones, elige la combinación que minimiza el costo total.

### E. Lock & Concurrencia en cargarTarjeta

```javascript
// ANTES DEL LOCK: todos los reads
const scores = ...; const cancha = ...; const stb = ...;

// DENTRO DEL LOCK (30s timeout): solo writes
const lock = LockService.getScriptLock();
lock.waitLock(30000);
sh.getRange(...).setValues(scores);
SpreadsheetApp.flush();
lock.releaseLock();
```
Soporta 18 jugadores cargando simultáneamente sin congelarse.

### G. API Externa: VistagolfSouth

- URL: `http://www.vistagolf.com.ar/handicap/DiferencialesArg.asp?strCampo=Campo1&strValor=<MAT>`
- Regex: `/HCP\s+Index\s*:?\s*([0-9]+[.,][0-9]+|[0-9]+)/i`
- Maneja coma y punto como separador decimal
- Timeout: 15s por request
- Batch paralelo con `UrlFetchApp.fetchAll()`
- Si falla: investigar greengolf.ai como alternativa (mencionado por el cliente)
